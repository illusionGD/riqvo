# D04 安卓真机原型：实现拆分

日期：2026-10-30。状态：待用户 review，尚未开始实现。依据总体计划 D04 与已确认的 WebdriverIO + Appium 路线。本轮不跳到 AI 开发，也不提前实现正式设备池及任务调度。

## 交付目标与边界

首轮在用户确认的 Windows 设备主机连接一台真实安卓手机，用平台工作台查看并操作手机 Chrome 页面，录制基础操作、编辑后回放，在两个环境复用步骤，查看真实截图和录像。沿用现有 Vue/Naive UI、共享 contracts、统一 HTTP 响应和 SSE 状态推送。

首轮建议 USB 连接，测试目标为 D02 可控站点，使用公开演示账号。手机上的 127.0.0.1 不代表设备主机；优先验证受控 adb reverse 映射两个站点端口，必要时使用手机可达的测试地址。Appium、ADB 控制面不直接对外暴露。Linux 云环境可做源码与协议验证，不作为桌面交付系统或安卓真机验收。

不在本轮完成：iPhone（D05）、AI（D06/D22～D25）、正式设备注册/租约/队列（D09）、用例库与正式持久报告、桌面安装包（D26）。已有 PC 原型仍须可用，不重构为未验证的统一驱动。

## 当前条件与需确认事项

- 仓库已有 contracts、PC 驱动、工作台及可控站点，尚无 driver-appium 包。
- 当前云环境未发现 adb/appium 命令，未取得可供本任务操作的真实安卓设备；不据此认定用户没有设备。
- 用户已确认首轮使用 Windows 电脑。Windows 版本、手机型号/Android 版本、Chrome 版本及主机可访问方式在 D04-01 登记；尚未获得直接操作该主机/真机的通道。macOS 保留为产品目标，后续另行验收。
- 如果没有真机，可完成代码与静态验证，但受影响验收标记阻塞；不能用模拟器、移动 viewport 或伪造响应勾选真机完成。

## 任务清单与实现顺序

### [ ] D04-01 · P0 · 连通性诊断与首次打开真实 Chrome

- 目标：用户能知道为什么连接失败，并在指定手机上打开测试网页。
- 实现：设备主机检查 ADB、USB 授权、设备状态、Chrome 与驱动兼容；显式选定设备，验证 Appium UiAutomator2/WebdriverIO 会话。固定经 Node 22 验证的依赖版本，记录 Android SDK/JDK 要求。首次连接安装的驱动辅助组件要在启动说明中列明，不宣称手机完全无需安装组件。
- 涉及：拟新增 `packages/driver-appium` 的公共连接/能力接口，`apps/runner` 诊断入口、启动文档；不要求数据库迁移。
- 前置：真实设备与 Windows/macOS 主机可用；无设备时仅交付诊断逻辑，首次连接验收保持阻塞。
- 产出：设备诊断结果、兼容版本表、可重复启动/关闭命令。
- 验收/测试：真实 Chrome 打开两个测试环境；未授权、离线、设备选择不明确、版本不兼容均有可解释错误；连接结束释放会话。仅操作显式选中的设备。

### [ ] D04-02 · P0 · 固定用例在安卓回放并给出正确结果

- 目标：先证明现有步骤协议能够驱动真机业务流程。
- 实现：适配导航、输入、点击、选择、勾选、等待、文本/可见性/URL 断言和截图；对 testId/CSS/label/role 逐项建立实测能力矩阵。不将 Playwright 的定位语义直接假定为 Appium 可用，也不将匹配多个元素默认当作唯一匹配。
- 涉及：driver-appium 执行入口、contracts 能力声明/结果校验、Runner 调用适配。
- 前置：D04-01。
- 产出：同一份协议用例的安卓执行结果与支持清单。
- 验收/测试：真实登录、表单、查询完成；正确断言通过、错误断言失败、无断言为未验证；不支持的动作执行前拒绝。能力不足时列出阻塞，不删减验收用例以掩盖差异。

### [ ] D04-03 · P0 · 平台查看并手动操作真机页面

- 目标：用户在平台内看到实际手机画面并执行基础网页操作。
- 实现：先验证画面采集、缩放坐标与 DOM/页面元素映射，处理浏览器工具栏、滚动和软键盘偏移；基础点击、滚动、输入逐项验证。具体画面传输采用实测可行方案，限制采集频率并在不可见/断开时释放资源；状态继续 SSE 推送，画面采集不恢复业务状态轮询。
- 涉及：driver-appium 观察/操作接口、Runner 受认证控制入口、Web 真机画面组件与 service/store。
- 前置：D04-01；复用 D04-02 的元素操作。
- 产出：工作台安卓设备选择、画面及手动操作入口。
- 验收/测试：点击、滚动后目标正确，软键盘出现后仍可输入；过期画面操作不盲目下发；控制请求有来源和会话校验，离线有提示。真实画面不以模拟截图替代。

### [ ] D04-04 · P0 · 手动操作录为可编辑步骤

- 目标：平台画面上的操作生成与 PC 相同格式的步骤草稿。
- 实现：把平台发起的操作结合当前页面元素信息转成语义步骤，导航后恢复观察，连续输入按合理粒度合并；密码仅在草稿中生成变量引用。先验证事件采集与上下文切换，不能把 Appium Inspector 当作可直接嵌入的产品录制器。
- 涉及：driver-appium 录制会话、contracts、Runner 草稿/SSE、现有步骤编辑器。
- 前置：D04-02、D04-03。
- 产出：可开始/停止的录制及可编辑草稿。
- 验收/测试：平台操作真机完成登录、创建、查询，步骤可修改后回放；密码值不进入草稿、导出、日志或状态事件。直接触摸物理手机是否可完整采集须单独实测；未覆盖时明确提示录制入口，不能假称全局触摸已被记录。

### [ ] D04-05 · P0 · 编辑后的用例复用于两个环境

- 目标：验证修改有效，并且无需重新录制即可更换 URL。
- 实现：复用现有站点映射、变量、步骤编辑及 JSON 导入导出；录制产生相对路径，不把测试环境域名固化到动作。明确手机的实际访问地址。
- 涉及：Web 编辑与环境配置、contracts 准备流程、Runner/driver-appium。
- 前置：D04-04。
- 产出：双环境样例与执行证据。
- 验收/测试：修改输入和断言后在两环境分别真实回放；结果绑定实际草稿快照；变量缺失、站点不可达不误报通过。PC 原型回归通过。

### [ ] D04-06 · P0 · 截图、录屏与网页播放

- 目标：成功和失败都有可定位的真实证据。
- 实现：验证 Appium/设备录屏链路的时长、分辨率与格式限制，开始/停止/异常时收尾；受控引用下载，前端播放实际录像。长录屏如需分段，明确展示分段及缺失状态，不伪装为连续视频。
- 涉及：driver-appium 产物采集、Runner 媒体接口、Web 报告播放。
- 前置：D04-02、D04-04；可与 D04-05 的业务验收组合执行。
- 产出：真实截图、录像、支持限制表。
- 验收/测试：记录真实操作并完成媒体解码和浏览器播放；覆盖成功、失败、取消、录屏不可用。媒体缺失和业务失败分别记录；实时画面不等同于已保存录像。产物保留策略产品化仍归 D18。

### [ ] D04-07 · P0 · 互斥、停止与断线后的资源回收

- 目标：避免一台手机被重复控制，以及异常后一直显示繁忙。
- 实现：原型内单设备会话互斥、停止/取消、超时和 USB 断线处理；重连先确认旧会话结束，禁止无条件重放可能重复提交的动作。这是本机原型互斥，不是 D09 分布式设备租约。
- 涉及：Runner 会话状态、driver-appium 生命周期、Web 错误状态及共享业务码。
- 前置：D04-03、D04-04、D04-06；基础清理从 D04-01 起持续实现。
- 产出：可恢复的状态与明确的异常记录。
- 验收/测试：重复启动被拒绝，取消后可重开；拔线、Appium 退出、页面关闭正确失败并尽力收尾产物；不能确认旧执行结束时不可再次派发，不把断线标为通过。

### [ ] D04-08 · P0 · 真机端到端验收及交付说明

- 目标：形成用户可以复现并 review 的完整安卓流程。
- 实现：运行“连接 → 平台操作 → 录制 → 修改 → 双环境回放 → 报告/录像”，补充移动菜单、iframe/标签页/文件交互的支持或阻塞说明，记录主机、手机、Chrome、Appium/驱动版本。
- 涉及：公开 HTTP/CLI/驱动 API 及 Web 验收流程、功能说明、维护 skill、进度。
- 前置：D04-01～07。
- 产出：真实运行证据、兼容矩阵、安装排障说明；全通过后迁移为长期 D04 说明并删除本临时计划。
- 验收/测试：Node 22 的格式、lint、typecheck、构建与相关 PC 回归通过；用户选定的 Windows + 真安卓完整链路通过。只对实测组合声明支持，macOS 未实测则列出验收缺口，正式双系统交付仍需 D26 完成。

## 优先级、风险与 review 节点

本次八项均为 D04 核心闭环的 P0；无线连接、更多型号、复杂手势与高帧率优化不阻塞首轮原型，新增时另拆 P1/P2。普通固定步骤重试、正式数据与账号池沿用后续功能，不暗中扩展本轮范围。

最大不确定性是平台画面操作与可重放元素定位的对应关系、Appium 版本组合和真机录屏限制。D04-01～04 先验证这些风险；若实测无法达到要求，展示证据并调整方案，不能以坐标回放取代稳定语义步骤却仍宣称跨设备兼容。

本计划先由用户 review；确认后按依赖逐项实现，完成一项更新勾选和验证记录，提交并 push dev 后暂停供 review，不跨到下一项。当前仅提交拆分计划，无业务代码、无依赖安装、无真机能力完成声明。
