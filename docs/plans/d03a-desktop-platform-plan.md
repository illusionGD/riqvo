# D03A 桌面执行器与平台 PC 闭环：调整后的实现计划

日期：2026-10-30。状态：待用户 review，本轮仅调整计划，不修改业务代码或重启服务。

## 为什么调整

D03 验证了执行核心，但当前页面直接连接本机原型服务；没有桌面 App、设备选择和正式的平台到执行器连接，用户打开云端页面不能据此控制自己的 Windows 浏览器。只继续开发手机驱动不能解决这个使用问题。

另有一个已观察到的预览故障：当前云环境 4318 的旧执行器仍返回 `{ token }`，新页面要求 `{ code, data, message }`，导致连接失败，录制/回放按钮禁用。这是待修复的运行版本问题，不是用户没有点击正确按钮；不推断用户本机也一定存在相同故障。

## 本阶段用户能完成什么

1. 在 Windows 安装并启动自己的桌面执行器 App，无需用户安装 Node 或输入 pnpm 命令。
2. 在 App 配置平台地址并完成配对；Web 设备页看到这台电脑及实际在线状态。
3. 在 Web 选择该 Windows 设备和测试 URL，点击录制，浏览器实际打开在这台 Windows 上。
4. 在该浏览器操作，Web 收到步骤；停止后编辑、添加断言并回放。
5. Web 查看本次及已保存的最小运行记录、截图和录像；断线/失败有明确原因。

平台可以部署在另一台可达机器；控制连接由执行器主动建立，不能把云端浏览器冒充用户电脑。首轮为 Windows，macOS 保留为后续桌面/iPhone 接入目标；Linux 只用于现有云开发，不新增上线或桌面交付范围。

## 模块与范围

拟新增 `apps/desktop`，作为执行器 UI 和进程生命周期入口，复用 `apps/runner` 和 `packages/driver-playwright`，不复制驱动。桌面壳建议优先评估 Electron，以降低 Node 执行核心接入成本；这是选型建议，尚未固定依赖或兼容结论，D03A-02 先提交选型与打包验证结果供 review。

Web 这一轮提供可用的设备页、录制工作台和最小运行记录页；不放置无法操作的项目、任务、AI 假入口。沿用 Naive UI、主题切换、`pnpm dev`、`0.0.0.0:5177`、共享 HTTP 响应和事件推送。

提前实现 D09 的最小设备绑定/状态/单任务派发、D16 的最小执行记录与证据、D26 的 Windows 基础安装启动。后续原功能继续补足团队共享、复杂队列、完整报告、签名/自动更新等，不重复造一套临时协议。D07 的完整账号/飞书/角色仍后续交付，但本阶段必须有最小操作者会话与设备配对授权，不能匿名控制设备，也不宣称多租户权限已完成。

## 实现任务

### [ ] D03A-01 · P0 · 修复当前预览与连接反馈

- 实现：确认预览进程和页面版本，安全重启当前受影响的空闲预览；为握手失败、协议不兼容、执行器未启动提供不同提示和明确下一步，禁用按钮解释原因。必要时增加协议版本检查，不能以兼容任意旧数据掩盖错误。
- 模块：Runner bootstrap、Web service/store/连接提示、启动说明。
- 前置：已知当前协议与运行状态；重启前确认无活动任务。
- 验收：当前预览可连接并完成真实 PC 原型回放；执行器停机或不兼容时能看懂原因，不静默禁用。明确云预览只能控制它连接的执行器，不表示用户电脑已接入。
- 测试：公开 HTTP/浏览器正常与错误握手、SSE 重连、录制/回放基础回归。
- 交付并暂停 review；这一步只修现有可用性，不作为桌面闭环完成。

### [ ] D03A-02 · P0 · 建立可启动的 Windows 桌面 App

- 实现：先确认桌面壳方案，建立 `apps/desktop`；App 展示平台地址、连接状态、浏览器依赖诊断、启动/停止执行核心。执行核心以独立受控进程运行，UI 崩溃不应留下不可管理的浏览器会话。默认关闭窗口/退出行为需明确展示。
- 模块：桌面工程、Runner 公共入口、开发与打包脚本。
- 前置：D03A-01；Windows 验证环境。Node 22 是项目执行工具链要求，桌面框架内置运行时兼容性须单独实测。
- 产出：实际可安装/启动的 Windows 测试包与卸载说明，非最终签名发行版。浏览器缺失时提供安装/定位指引；不默默下载未知可执行文件。
- 验收：用户不运行 pnpm，也能启动 App 和本机执行核心；重复启动、依赖缺失、端口占用有反馈；退出回收进程。Linux 构建成功不能代替 Windows 安装验收。
- 测试：真实 Windows 安装、启动、退出及错误路径；桌面渲染层不开放任意系统命令能力。

### [ ] D03A-03 · P0 · App 与平台配对，设备页显示真实状态

- 实现：最小操作者会话保护、一次性配对授权、执行器身份凭据、主动认证连接、心跳及失效判断。Web 显示设备名称、系统、浏览器能力、在线/离线/忙碌；解绑后禁止继续控制。配对信息与设备归属持久化。
- 模块：NestJS 设备/配对模块与 MySQL 迁移、contracts、App/Runner 连接、Web 设备页。
- 前置：D03A-02。
- 产出：可识别和选择的真实 Windows 节点；复用至 D09 的连接协议。
- 验收：平台和执行电脑分机可达时能配对并显示状态；错误/过期/重复使用的配对凭据被拒绝；断网显示离线，重连不创建重复设备。不能只依赖浏览器传入设备 ID 获得控制权。
- 测试：公开配对/解绑接口、隔离 MySQL 持久化、真实桌面连接和断线。是否具备分机测试网络在实现前确认。

### [ ] D03A-04 · P0 · Web 选择设备，发起真实 Windows 录制

- 实现：工作台必须选定在线设备，启动指令经平台派发给该执行器；受控浏览器在 Windows 打开。手动操作发生在测试浏览器，草稿步骤与状态回传 Web。录制停止、取消和设备忙均有可见状态。
- 模块：平台命令/事件通道、Runner 单会话互斥、Web 设备选择及录制工作台、现有 PC 驱动。
- 前置：D03A-03。
- 产出：从 Web 到指定设备的录制闭环，替换“默认控制 Web 服务所在电脑”的隐式行为。
- 验收：平台不在 Windows 上时，点击录制仍在选定 Windows 打开浏览器；重复请求不重复开会话；其他设备不被误操作；密码只记录变量引用，模型 Key 不涉及本阶段。
- 测试：Windows 录制/停止/取消、命令确认与去重、授权/忙碌拒绝、状态重连后草稿不被错误覆盖。

### [ ] D03A-05 · P0 · 编辑后在指定设备回放，保存最小运行记录

- 实现：复用步骤编辑、环境 URL 映射与变量；固定运行快照后派发。MySQL 保存执行 ID、目标设备、快照和状态、步骤结果；任务消息仅用必要数据及受控引用，敏感值不进入报告。支持后台/可视回放、取消、单设备原型互斥，不引入完整批量调度。
- 模块：NestJS 最小运行模块及迁移、Runner 执行适配、contracts、Web 回放与运行列表。
- 前置：D03A-04。
- 产出：可重访的运行详情，复用至 D16；浏览器现场不作为持久化数据。
- 验收：编辑后行为改变，同一步骤在两个 URL 环境运行；错误断言失败、无断言未验证。刷新页面保留运行记录；服务重启可追溯已有记录，未完成任务标异常/待核对，不能自动重做可能有副作用的操作。
- 测试：公共 HTTP/真实 Windows 业务流程、快照隔离、取消、重启恢复记录、重复派发与断线歧义。

### [ ] D03A-06 · P0 · 平台查看真实截图和录像

- 实现：执行器将产物按受控协议上传平台存储，关联运行记录；不能让远端 Web 引用 Windows 本地路径。上传和录屏失败单独显示，不覆盖业务结果；媒体访问鉴权，支持实际视频播放及 Range。
- 模块：Runner 产物上传、NestJS 存储/访问接口、Web 最小报告。
- 前置：D03A-05。
- 产出：跨机器可查看的步骤证据，复用至 D16；完整保留策略仍由 D18 完成。
- 验收：Windows 真实录制/回放录像可在平台播放、截图可查看；未上传/丢失明确显示；越权、伪造引用或本地路径访问被拒绝，传输失败不变成测试通过。
- 测试：真实媒体解码与网页播放、产物引用及访问控制、上传中断与可重试行为。

### [ ] D03A-07 · P0 · Windows 完整体验验收与交付

- 实现：按用户路径从安装 App 到 Web 设备选择、录制、编辑、双环境回放、查看记录/证据完整走通；补齐启动、网络可达、浏览器依赖和错误排查说明。
- 前置：D03A-01～06；用户 Windows 主机与可访问测试站点。
- 验收：操作者无需开发命令即可使用桌面端；平台可说明任务在哪台电脑执行；App 退出或网络断开后设备状态、任务结果、资源释放正确。原 PC 驱动及 HTTP 响应回归通过。
- 产出：Windows 测试包、验收证据、版本及已知限制、长期功能说明和维护 skill。未实测的 macOS、签名与升级能力明确不计为完成。
- 完成后删除本临时计划，将证据迁移到长期说明；每个小项仍按完成、push dev、暂停 review 的流程交付。

## 后续顺序与优先级

上述七项均为可用闭环的 P0。进入 D04 前必须完成 D03A 的 Windows 真机闭环，安卓通过同一个桌面 App 接入，不再建立一套独立的用户启动方式。

- D04：Windows App 连接安卓 Chrome，复用设备选择、命令、事件及证据通道；原拆分计划保留但暂停，恢复前按实际桌面接口再 review。
- D05：扩展 macOS 桌面宿主，并接入 Mac/Xcode/WDA/iPhone Safari；macOS App 不等到 D26 才建立。
- D06：在已可操作的真机闭环上完成最小 AI 验证。
- D07～D25：账号/项目、正式设备共享与队列、用例库、数据、报告、定时和 AI 等，继续按依赖推进；已经前置的最小能力扩展而不重复实现。
- D26：完整 Windows/macOS 发行验收、签名/安装升级、备份恢复及交付文档，保留原 P0 完整交付要求。

托盘细节、开机启动、自动更新和多设备批量并发可后续单独拆 P1；本轮不以增加空导航代替业务能力。UI 要明确区分“当前不可用的原因”和“尚未实现”。
