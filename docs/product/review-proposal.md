# Web 自动化测试平台：功能设计与交付计划

编制日期：2026-10-28。确认日期：2026-10-29。状态：用户已统一确认全部 8 组，尚未实施。

用户已统一确认本文 8 组的功能范围、默认行为及交付安排，作为后续设计和开发基线。保留条目编号用于追踪实现和后续变更；文中需通过原型验证的实际能力、兼容组合和性能仍属于验证工作，不表示已经实现或测试通过。

功能总览见 [功能清单](features.md)，技术依据见 [方案调研](../research/web-test-platform.md)。本文记录确认后的产品行为；实际浏览器、真机与模型能力仍须通过原型验证。

沿用的主要决定：

- 面向测试团队，测试 PC 网页、安卓 Chrome 和 iPhone Safari，优先真机；采用 NestJS、MySQL，管理平台与测试执行器分开部署。
- 支持录制、编辑、回放、视频、需求生成用例及 AI 自主探索；环境自定义，同一用例可跨环境复用。
- 默认后台执行，支持可视化；普通用例优先复用有效登录状态，失败默认额外重试 1 次，保留各次结果。
- 回放录像默认覆盖成功、失败及重试；视频、执行截图、Trace 默认保留 30 天，报告与结果 180 天，期限可配置，重要运行可长期保留。
- 个人 AI Key 只在平台网页本地持久化；启动任务时允许交给本人本机执行器的隔离 AI 进程临时内存使用，结束清除，不上传平台后端或写入执行器磁盘。团队 Key 后端加密保存，默认使用团队模型。
- 测试始终发生在选定真机上。个人 AI 在本人本机直连；团队 AI 按设备归属分流，自管真机在其执行主机上运行 AI 并直连，第三方真机由平台服务端运行 AI 并远程操作。凭据、截图与在线边界见 [架构设计](../architecture/ai-execution.md)。
- AI 权限按环境、业务动作及适用页面配置；团队模型支持项目和成员额度；等待人工默认 10 分钟，超时释放设备并保留记录。
- 需求输入优先飞书链接和 Markdown；Word、PDF、直接输入也纳入总范围。通知优先平台、邮件、飞书，企业微信和钉钉后续接入。
- 平台支持账号密码和飞书登录、邀请与自助注册、预设及自定义角色；新成员默认只读，仅能查看已加入的项目。

## 1. 报告与协作

| 编号 | 已确认行为 |
| --- | --- |
| 1.1 导出格式 | PDF、Markdown、HTML 离线包都支持。PDF 包含摘要、失败步骤、预期与实际、关键截图；Markdown 便于编辑和归档；HTML 可离线查看步骤，按需打包尚存的截图、视频和适用的 Trace。 |
| 1.2 导出范围 | 导出前可选用例、步骤及附件，默认包含摘要和失败证据。离线包带本地资源，不依赖平台登录或在线图片地址；已清理产物列为缺失，不生成假链接。Trace 提供文件及对应查看说明，不承诺所有 Trace 都能直接在离线 HTML 内播放。 |
| 1.3 协作与问题 | 支持按用例、步骤或视频时间点评论、批注、指定负责人及标记待处理、已确认、已解决、已关闭。首版支持绑定外部缺陷链接和复制缺陷摘要；直接创建、同步 Jira 或飞书项目缺陷放到扩展版。 |
| 1.4 外部分享 | 沿用免登录临时链接能力，默认有效期 7 天并启用访问密码，项目可调整。外部默认只读摘要及主动勾选的证据；原始日志、Trace 和测试数据不默认公开。项目负责人默认有分享管理权，可通过自定义角色授权。普通通知仍发送需登录的内部链接。 |
| 1.5 分享有效性 | 报告、截图、视频等均校验分享范围和有效期；撤销后链接及经该分享访问的产物失效。分享不自动延长产物保留时间，创建时提示预计到期情况。撤销链接不回收对方已经下载的文件。 |
| 1.6 录制与音频 | 录制工作台也默认录屏，录制与回放的录像策略分别配置；取消录制时允许丢弃未保存的草稿录像。首版无音频，音频如以后需要，按平台能力单独提供。 |
| 1.7 清理规则 | 从本次运行或录制结束时起算保留期；策略修改默认影响新记录，已有记录可批量调整。执行日志按产物期限管理，结构化步骤结果随报告保留。在用截图基准随基准版本管理，不作为普通执行截图按 30 天删除。 |
| 1.8 长期保留与脱敏 | 项目负责人可设置或解除长期保留，也可授权其他角色。报告到期清理时检查仍需保留的附件引用。密码等变量在日志和导出中默认遮蔽，视频与截图可预览后排除或做遮罩；首版不承诺自动识别全部画面敏感信息。 |

设计考虑：同一份结果可以用于在线排查、文档汇报和离线交付；导出和分享均明确证据范围，保留期限不会因分享而隐式改变。

## 2. 执行与调度

| 编号 | 已确认行为 |
| --- | --- |
| 2.1 批量运行 | 一次选择多个环境、浏览器或设备、数据集，生成运行组合。启动前显示组合数、兼容情况及资源需求，例如 2 个环境 × 3 类设备 × 4 组数据为 24 个组合。不支持的组合标明不兼容，不算通过。 |
| 2.2 用例独立性与失败 | 默认用例相互独立，资源允许时并行；单个用例关键步骤失败后停止该用例，其他独立用例继续。支持顺序执行、前置依赖和整套失败即停。依赖失败时，下游标记“因依赖未执行”；流程内有依赖的步骤优先放在同一用例或公共流程中。 |
| 2.3 重试 | 沿用默认重试 1 次，可关闭或调整。平台默认、项目默认、用例设置和有权限的单次覆盖依次生效。定位、等待、断言失败可重试整个用例，从已知前置状态开始；支付、发消息、提交订单等有副作用的流程需先定义可重复执行条件或恢复办法，状态不明时停止自动重试。 |
| 2.4 异常分类 | 人工取消、权限阻止、额度耗尽、等待人工超时不自动当作普通失败重试。设备断线标记执行异常，确认旧执行已停止、资源可用后，再按用例恢复规则重跑。每次尝试独立保存，重试通过仍显示最初失败。 |
| 2.5 运行中查看与接管 | 首版可随时查看进度、日志和当前截图；手机实时画面可打开或收起。PC 的后台/可视化启动模式运行前选择，运行中修改启动模式下次生效。PC 可视化会话可暂停接管，后台会话的实时远程画面接管先通过原型验证再列为正式能力。 |
| 2.6 暂停与调试 | 提供单步、断点、暂停、继续和停止。调试结束默认关闭执行会话，允许显式选择保留现场，保留上限沿用项目人工等待时长。保存登录状态不等于长期占用浏览器或手机。 |
| 2.7 定时与重叠 | 提供每天、每周、固定间隔及高级 Cron，时区按项目显式设置，创建时采用浏览器时区并展示下次执行时间。同一计划上次仍在运行时，默认跳过本次并留下记录，可改为排队或允许并行。手动和发布触发默认进入资源队列。 |
| 2.8 发布检查 | 发布系统传入环境、版本和用例套件，重复请求使用同一触发标识避免重复创建任务。返回任务 ID、报告地址和机器可读结果。默认要求所有必跑组合完成且通过；“重试后通过”可通过但附警告，可配置严格模式；失败、未完成、无验证结果或非预期跳过不通过检查。 |

设计考虑：明确区分独立用例、流程依赖和资源不足，避免一次失败停止所有无关测试，也避免重试重复制造业务副作用。

## 3. 测试数据与账号

| 编号 | 已确认行为 |
| --- | --- |
| 3.1 数据集 | 支持平台表格编辑及 CSV、Excel 导入；提供模板、类型校验和导入预览。数据集有版本，每行可作为一个独立测试输入，报告关联实际使用的行及版本。 |
| 3.2 参数与环境 | 用例引用逻辑变量，环境提供网站地址和测试账号，数据集提供业务输入；显式覆盖在启动预览中显示。环境地址、凭据引用与 AI 权限受各自权限控制，不能由普通数据列绕过。 |
| 3.3 测试账号池 | 账号按项目和环境管理。默认同一环境下一个账号同时分配给一个任务，空闲账号不足时排队，避免同账号互踢或修改同一份数据。明确支持多会话的账号可配置共享。会话恢复仍按环境、账号及设备分别处理，恢复失败回到登录流程。 |
| 3.4 凭据与数据 | 项目共享的被测网站账号密码、登录状态等敏感材料加密保存，仅在有权限的执行任务中使用，界面显示引用或掩码，导出不含密钥。个人 AI Key 继续遵守只在本地使用的已确认规则。 |
| 3.5 文件素材 | 支持项目素材库，上传图片、PDF、表格等测试文件，用例引用文件版本而非某台电脑的绝对路径。设置类型和大小限制，运行前将需要的素材送到执行器；手机上传、文件选择能力按驱动验证。 |
| 3.6 准备与清理 | 支持前置准备和结束清理流程，测试数据使用运行编号标记。清理只处理本次明确创建或声明可清理的数据；失败或取消后仍尝试清理，清理异常单独记录，不覆盖原始测试结果。 |
| 3.7 人工接管 | 普通固定步骤遇到验证码或二次验证也采用“等待人工”，沿用默认 10 分钟及项目配置；超时标记未完成并释放设备。接管完成后验证当前页面与后续步骤的前置条件再继续。 |

设计考虑：让同一用例能使用多组数据，同时避免并行任务争用账号；测试人员不必维护各执行电脑上的文件路径。

## 4. 录制、编辑与检查

| 编号 | 已确认行为 |
| --- | --- |
| 4.1 首版交互 | 支持点击、输入、下拉选择、勾选、滚动、导航、等待、普通弹窗、多标签页、iframe；PC 增加悬停、双击及常见按键，手机支持点击和滑动。文件上传纳入原型验证。复杂拖拽、画布、富文本、手势组合和系统级弹窗逐项扩展，对不支持的动作明确提示并允许补充步骤。 |
| 4.2 录制中编辑 | 支持修改步骤名称、参数和插入检查。已经执行过的步骤修改只作用于草稿，重新试跑才验证新行为。暂停录制时的操作不自动成为步骤；恢复时记录当前页面状态并提示补录必要前置过程。 |
| 4.3 可视化编辑 | 首版采用步骤列表加参数面板，支持 if/else、按数据遍历、固定次数循环及公共流程。循环默认上限 100 次，可配置；普通元素等待默认 30 秒，允许项目及步骤覆盖。跨端差异使用明确的“PC/手机”条件分支或平台专用子流程。 |
| 4.4 脚本扩展 | 支持 TypeScript/JavaScript，通过平台提供的测试 SDK 操作页面、变量和授权接口。使用独立执行进程及必要的系统隔离，只注入声明的测试数据；脚本不获得 AI 模型 Key。首版按可信项目代码管理脚本编辑及执行权限，不允许随意安装 npm 包。不能把 Node.js vm 当作完整隔离边界。 |
| 4.5 检查范围 | 页面文本、元素状态、URL、数量和截图检查纳入首版。支持显式 HTTP 请求及状态码、响应字段断言；与当前页面关联的网络捕获先支持已验证的 PC 驱动。下载文件先支持 PC 的名称、大小、校验值及基础文本/JSON/CSV 内容检查，手机按真实文件获取能力扩展。 |
| 4.6 判定结果 | 关键步骤和检查失败默认停止当前用例；允许将检查设为“失败后继续收集证据”，该用例最终仍失败。没有业务检查的用例显示“执行完成，未验证”，不计为验证通过；作为其他用例前置步骤的公共流程可以没有独立断言。 |
| 4.7 截图基准 | 基准需由有基准管理权限的成员确认并版本化；缺少匹配基准时标记待确认。先支持当前视口和元素截图，整页截图按平台验证。差异像素比例默认容忍 0.1%，可按项目或基准覆盖；同时展示实际差异，不把该数值描述为已验证适合所有页面。 |
| 4.8 公共流程与导出 | 沿用固定引用版本、用户确认升级。批量升级先生成草稿并试跑，再逐个或批量保存新版本；旧运行继续关联旧版本。首版支持平台 JSON 格式导入导出，附依赖版本及素材清单，凭据通过导入映射补齐。后续提供对应驱动的脚本导出，不承诺任意脚本可无损导回可视化步骤。 |

设计考虑：首版围绕常见 Web 交互形成稳定闭环，复杂场景有明确扩展路径；用例“点完了”和“验证通过”分别展示。

## 5. 设备与浏览器范围

| 编号 | 已确认行为 |
| --- | --- |
| 5.1 首批目标 | PC 优先 Chrome、Edge；真机至少一台安卓 Chrome、一台 iPhone Safari。PC Firefox、macOS Safari 及更多机型进入扩展版。按实际系统和浏览器版本登记已验证组合；Playwright WebKit 不标成真实 Safari，移动模拟不标成真机结果。 |
| 5.2 执行节点 | PC 执行端支持按能力接入 Windows、macOS、Linux，具体浏览器组合经验证后开放。iPhone 首版采用 Mac、Xcode 和真机的标准链路；手机执行可以集中在团队设备电脑上，成员通过平台使用。 |
| 5.3 设备归属 | 默认项目专用，也支持管理员将设备分配给指定项目共享。设备池按平台、系统版本、浏览器和标签筛选，用户可选择固定设备或满足条件的空闲设备。 |
| 5.4 并发与队列 | 一台手机同时只允许一个任务；PC 按执行电脑资源配置并发，初始默认 2 个会话并通过原型调优。交互录制和人工调试可获得排队优先级，但不抢占正在运行的任务。 |
| 5.5 断线与恢复 | 设备健康、连接状态和排队原因可见。断线后停止派发，当前任务标记异常；只有确认旧执行停止、设备恢复可用后才释放隔离并重新派发。重跑从用例前置状态开始，不默认从断线步骤继续。 |
| 5.6 云真机 | 保持自有设备优先。首个云服务候选为 BrowserStack，Sauce Labs 为备选；接入前验证移动网页自动化、视频、内网站点访问、地区及费用。先接一个可替换的供应商适配器，后续按机型和网络需求增加其他服务。 |

设计考虑：先验证三个主要使用端，设备池接口允许后续扩展机型和供应商；硬件兼容结果以真实执行记录为准。

## 6. AI 剩余功能范围

| 编号 | 已确认行为 |
| --- | --- |
| 6.1 文档解析 | 首版支持飞书文档、Markdown、直接输入，提取正文、常见表格及可访问的内嵌图片；图片理解要求所选模型具备图像能力。Word、文本 PDF 后续接入，扫描 PDF 加 OCR 再扩展；识别不清或缺少业务定义的部分标注待补充，不自行补成断言。 |
| 6.2 文档更新 | 飞书默认每 15 分钟检查一次，可配置并支持手动刷新；结合实际授权与接口限流调整。更新只提醒、展示差异及受影响用例，用户决定是否生成修改草稿。Markdown 新版本上传后也展示差异，已保存用例保持原版本，操作者保存修改时创建新版本。 |
| 6.3 生成流程 | 沿用场景先确认、再生成步骤和试跑。场景按每批 10 条展示，允许增加、删改、合并及分页，不将 10 条作为覆盖上限；每个场景关联需求来源、前置条件及预期。编辑页并列显示生成依据、步骤、试跑证据与修改差异，操作者可直接编辑、保存和试跑，无需独立审批。 |
| 6.4 修复与自动试跑 | 已授权范围内，生成草稿试跑失败后默认自动修订 1 轮，可配置；优先修复定位、等待和页面步骤问题。已有用例的修复生成新草稿，由操作者直接编辑、保存或试跑，保存时创建新版本；不自动删除断言、放宽预期或把步骤跳过来换取通过。AI 修订轮数与普通用例重试次数分开配置和显示，并受任务总预算约束。 |
| 6.5 模型接入顺序 | 首版建立 OpenAI 兼容协议、自定义地址及厂商适配器，优先验证 OpenAI、Anthropic、Gemini、DeepSeek、通义千问等候选。后续扩展豆包、智谱、Kimi、文心、混元、讯飞及其他国内外服务；这是验证顺序，不是已兼容清单。模型选择展示文本、图像、工具调用能力，不按品牌自动假定能力相同。 |
| 6.6 模型选择与自动任务 | 项目默认使用授权的团队模型，手动任务可选择个人模型。定时和发布任务默认绑定团队模型及明确责任人；个人模型需要网页为当前任务交接临时 Key，本人本机在线且凭据有效。新任务不能从执行器磁盘恢复 Key，未就绪时报告资源缺失，不擅自切换模型或计费账号。 |
| 6.7 探索与费用 | 自主探索默认上限为有效执行 20 分钟或 100 个动作，先达到者停止并生成“达到探索上限”的报告，不宣称全站通过。上限可配置，等待人工期间暂停有效时间和模型循环，设备实际占用时间另记。团队额度按月统计 Token，用量按项目和责任人双重检查，80% 提醒、达到限额暂停；费用单列为估算，缺少供应商用量时标明估算来源并保守计量。 |
| 6.8 统一权限 | 需求生成时的页面操作、自动试跑、修复试跑、自主探索都遵守目标环境权限。固定回放也受环境执行权限和已声明业务动作规则约束，但不为每步额外调用 AI 分类；未知动作需显式声明或人工确认。脚本受单独授权，对要求严格只读的环境结合受限测试账号及执行能力控制，不仅靠按钮名称判断。 |
| 6.9 权限与暂停 | 创建环境时提供只读、常规测试、自定义模板，默认选择只读，管理员可修改，环境名称不决定模板。人工确认绑定具体环境、任务及动作范围；禁止规则不能用一次确认越过。运行中权限收紧在下一动作前生效，放宽后需明确重新授权；保留策略版本和确认记录。 |
| 6.10 任务恢复 | 人工处理后重新读取页面状态，确认仍满足后续前置条件；异常则生成恢复建议，不盲目继续。额度不足暂停时保留进度，设备现场最多保留项目人工等待时长，超过后释放；补充额度可重新调度，现场已丢失时从可重建的前置状态恢复，无法恢复时重新运行并保留旧记录。 |
| 6.11 调用位置与画面 | 个人 AI 本机直连，个人 Key 仅网页本地持久化、本人本机临时使用。团队自管真机由授权设备主机的独立 AI 进程直连，团队 Key 临时内存使用；第三方真机由平台服务端 AI 调用模型，Key 不下发第三方。两条团队路径均校验权限和调用前额度，测试仍在选定真机上执行。截图和视频异步归档，不作为每一步 AI 决策的前置等待。 |

设计考虑：AI 以可编辑、可复现的用例为主要产出，模型调用、动作权限和预算统一约束；失败、未完成、达到探索上限均有明确结果。

## 7. 项目与外部集成

| 编号 | 已确认行为 |
| --- | --- |
| 7.1 项目与站点 | 一个项目对应一个业务系统，可配置多个命名站点，例如用户端、管理端、登录中心；每个环境分别映射地址，支持声明的 SSO 跳转。环境变量、测试数据、角色和用例仍在项目内管理。归档项目保留历史记录，停止新任务及定时触发。 |
| 7.2 初始化与邀请 | 首个管理员通过部署时一次性初始化创建；普通自助注册不会自动成为管理员。邀请可按平台账号或邀请链接发起，链接默认 7 天有效、可撤销，绑定预期身份并只使用一次。加入项目默认只读，邀请人有授权时可预设其他角色。 |
| 7.3 身份与恢复 | 已登录用户验证当前身份后绑定飞书，避免只因邮箱相同就合并账号。解绑前确保仍有可用登录方式；支持账号密码重置和管理员协助恢复，并记录身份及权限变更。 |
| 7.4 默认权限 | 只读成员查看已加入项目；测试成员编辑及保存用例、运行有权执行的用例、评论及导出获准报告；项目负责人管理环境、成员、共享凭据、外部分享和长期保留。保存用例、运行测试、基准更新、脚本执行、AI 动作确认等是可单独授权的能力，预设角色可通过自定义角色补充。 |
| 7.5 保存与版本管理 | 用例保存成版本后，有执行权限的人可直接运行；草稿可直接试跑并保存本次执行快照。保留版本历史、修改差异及恢复旧版，运行记录绑定实际版本。取消用例审批、审核人、审批状态和环境版本审核开关，无需额外发布或批准步骤；执行仍按所选环境及成员权限校验。 |
| 7.6 飞书 | 优先对接企业自建应用，分别配置登录、文档读取、通知权限。文档优先由应用身份访问已明确授权的文档；飞书登录不自动授予全部文档读取权限。通知包含摘要和报告链接，文档、Wiki 页面按实际接口能力逐项接入。 |
| 7.7 集成凭据 | 团队飞书应用、邮件、云真机、发布对接凭据由后端加密保存，按项目或平台管理权限调用，记录使用与轮换，日志不回显。个人 AI Key 的本地规则继续生效；额外的个人文档授权若以后加入，应有独立授权及撤销入口。 |
| 7.8 外部触发（可选接入） | 平台独立使用，手动和定时测试无需绑定代码仓库或接入 GitHub、GitLab、Jenkins。首版保留带项目权限的通用触发 API、任务查询和结果回调，提供 JSON/JUnit 结果；需要发布后自动测试时，由实际发布流程按需调用。特定平台的专用对接、插件及示例不作为首版必需交付。 |
| 7.9 通知规则 | 通过平台、邮件、飞书订阅最终失败、重试后通过、等待人工、设备异常、额度告警、需求文档变化和运行摘要。最终失败在重试结束后通知，等待人工立即通知；普通成功默认只进汇总，按项目可调整接收人、事件及频率。企业微信和钉钉沿用相同事件接口后续接入。 |

设计考虑：一个业务系统可以覆盖多个入口，身份、文档权限、执行权限分别管理；发布系统和通知渠道通过统一接口接入。

## 8. 首版范围与交付顺序

已确认先做原型，再交付可供团队内测的 V1，随后扩展能力。V1 内部分里程碑交付，完整验收包含 PC、安卓、iPhone 和基础 AI。

| 阶段 | 交付范围 | 验收目标 |
| --- | --- | --- |
| P0 技术验证 | 一台 PC、一台安卓、一台 iPhone、两套 URL；验证受控录制、编辑、回放、视频、统一步骤及最小 AI 生成链路 | 同一代表性业务流程在三端和两套环境执行，检查能分辨正确与错误结果；视频可播放；设备异常有结果并能释放；记录真实能力缺口 |
| V1 里程碑一 | 账号密码及飞书登录、项目角色、自定义环境、自有设备池、录制和编辑、固定回放、测试数据、账号复用、公共流程版本、基础脚本、页面断言及截图基准 | 测试人员可独立录制、修改并跨环境运行；失败可定位；并发和账号分配有明确边界；三端分别验收 |
| V1 里程碑二 | 视频与报告、保留清理、三种报告导出、外部分享、评论及问题标记、批量运行、定时和发布触发、平台/邮件/飞书通知 | 完成“触发测试 → 查看报告 → 分享/导出 → 通知处理”的完整流程；权限、过期与历史记录可验证 |
| V1 里程碑三 | 飞书/Markdown/文字生成用例、基础页面探索、试跑与修复草稿、个人/团队模型、额度、环境动作权限和人工接管；首批候选模型通过能力验证 | 需求先确认场景，再生成带检查的可编辑用例并在三端试跑；人工及额度暂停有明确恢复结果；个人 Key 不进入平台后端 |
| V2 扩展版 | Word/PDF/OCR、更多模型、首个云真机服务、Firefox 与 macOS Safari、更多真机和复杂交互、移动端文件及网络检查、驱动脚本导出、缺陷系统双向集成、企业微信/钉钉 | 按实际新增能力建立兼容矩阵和验收用例，原有用例、权限与报告继续兼容 |

三个 V1 里程碑属于同一个首版内测目标，完成里程碑三后才算满足已确认的完整首版范围。P0 发现的能力限制应明确反馈到范围和体验，不能把模拟器结果当作真机验收。

完整首版还包含首版范围内的显式 HTTP 检查、PC 基础下载检查、平台 JSON 用例导入导出。云真机、其余模型和通知渠道保留在总功能范围，按已确认优先级逐步交付。

阶段通用验收要求：

- 按真实浏览器和设备分别展示通过、失败、重试后通过、未完成和不支持；无断言的执行不会被统计为验证通过。
- 切换环境后地址、账号、数据和权限正确隔离；公共流程与用例版本可追溯。
- 个人与团队模型的调用路径和密钥归属符合已确认规则；脚本、日志、队列和分享不包含模型 Key。
- 普通失败、断线、人工超时、额度暂停和清理异常均有可解释状态及资源释放或恢复路径。
- 分享失效、保留期清理和长期保留按配置生效，缺失证据有明确提示。

当前尚无真实设备验证结果、团队规模和可用开发人力，尚未承诺日历工期。先完成 P0，再按上述已确认里程碑估算工作量；后续调整范围或交付安排时记录变更，不将兼容性限制静默视为需求已完成。
