# riqvo 开发功能计划

日期：2026-10-29。状态：D01 已实现并验证，暂停等待用户 review。每个功能完成并验证后，提交并 push 到 `origin/dev`，随后暂停，等用户 review 后再开始下一个功能；进度见 [progress.md](progress.md)。

目标：为测试团队交付可视化 Web 自动化测试平台，覆盖 PC 浏览器、安卓 Chrome 真机和 iPhone Safari 真机，完成录制、编辑、回放、视频报告、需求驱动生成和 AI 探索。

产品基线：[功能清单](product/features.md)、[功能设计与交付计划](product/review-proposal.md)。技术依据：[方案调研](research/web-test-platform.md)。本计划拆分开发顺序与验收要求，沿用已确认的功能及最近的调整：用例保存后按权限直接运行，外部发布系统按需调用通用接口。

## 1. 优先级与交付阶段

| 优先级 | 含义                             | 开发安排                                                           |
| ------ | -------------------------------- | ------------------------------------------------------------------ |
| P0     | 核心流程、必要基础及关键技术验证 | 依赖满足后优先开发；缺失时无法完成首版核心验收                     |
| P1     | 首版团队使用和交付能力           | 可在对应里程碑内后移；表中归属 V1 的 P1 项仍须在完整首版验收前完成 |
| P2     | 已确认的后续扩展功能             | 在 V1 完成后逐项建设                                               |

执行时先满足依赖，再按优先级安排。同一阶段内没有依赖的事项可以独立推进。以下阶段编号与优先级分开：

| 阶段            | 对应既有安排        | 完成结果                                                     |
| --------------- | ------------------- | ------------------------------------------------------------ |
| M0 技术验证     | 原方案“P0 技术验证” | 三端、两套 URL、录制回放录像及最小 AI 链路有真实验证结果     |
| V1-A 基础测试   | V1 里程碑一         | 成员能配置项目、环境、设备和数据，独立录制、编辑、运行及调试 |
| V1-B 报告与协作 | V1 里程碑二         | 能批量或定时运行，排查、导出、分享结果并接收通知             |
| V1-C 基础 AI    | V1 里程碑三         | 需求生成、探索、修复草稿、个人/团队模型、额度和人工接管可用  |
| V2 扩展         | 已确认扩展版        | 增加文档格式、模型、设备、浏览器、交互和集成能力             |

**完整 V1 = V1-A + V1-B + V1-C + D26 交付验收，包含 PC、安卓、iPhone 和基础 AI。**

## 2. 项目规则与技术准备

本次已阅读仓库两份 rules、8 个 SKILL.md，以及 TDD 的 tests.md、mocking.md。

| 来源                                                                                           | 本计划的应用方式                                                               |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| [project-plan](../.codex/skills/project-plan/SKILL.md)                                         | 复用已确认调研，生成本总体 plan；开发启动后维护 progress.md                    |
| [research](../.codex/skills/research/SKILL.md)                                                 | 沿用既有方案；新增重大选型或原型发现能力缺口时补充针对性调研                   |
| [to-tickets](../.codex/skills/to-tickets/SKILL.md)、[coding](../.codex/skills/coding/SKILL.md) | 开发到对应大功能时再拆小任务，按依赖实施并记录结果                             |
| [tdd](../.codex/skills/tdd/SKILL.md) 及附属指南                                                | 在统一评审的公共测试边界上，按行为逐项红—绿验证，避免实现耦合测试              |
| [前端代码规则](../.codex/rules/frontend-code-standards.md)                                     | Vue SFC、Pinia Setup Store、显式类型、JSDoc、SCSS/BEM 及格式检查               |
| [工程结构规则](../.codex/rules/vue3-vite-ts-project-structure.md)                              | 应用于 apps/web/src，保持 views、components、stores、services 等职责和依赖方向 |

foundation、data-foundation 的内容属于 Memory Weave，未将其中的业务模型、数据库组合、固定版本或仓库操作授权用于 riqvo；plugin-article 用于文章写作，本次不适用。rules 中部分链接仍指向旧的 .cursor/.mdc 路径，实际依据为本仓库以上两份 .codex/rules/*.md。

工程采用 pnpm workspace，按下面的边界维护；Node、pnpm、数据库、浏览器及驱动的具体兼容版本在 D01 和 M0 固定并记录。

| 模块                                      | 技术与职责                                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| apps/web                                  | Vue 3 + Vite + TypeScript + Pinia；页面装配、录制及编辑界面、报告                                                 |
| apps/api                                  | NestJS + TypeScript 模块化单体；认证、项目、用例、环境、任务、产物与 AI 管理                                      |
| apps/runner                               | 独立执行核心；本机以自研桌面执行器 App 接入，也可部署为服务器进程；测试电脑、安卓主机及 Mac/iPhone 节点按能力接入 |
| packages/contracts、test-engine           | 统一步骤、版本、任务、结果协议及执行流程；人工录制与 AI 生成共用                                                  |
| packages/driver-playwright、driver-appium | PC 使用 Playwright；真机使用 WebdriverIO + Appium                                                                 |
| packages/ai-agent                         | 后端团队 AI 任务与个人执行端复用模型适配及工具协议                                                                |
| 数据与任务                                | MySQL 保存业务和版本元数据；Redis/BullMQ 管理任务；独立文件/对象存储保存视频等产物                                |

源码导入、目录与命名遵循现有 rules；工程建立时配置 lint、typecheck、Prettier、构建和测试命令，验证构建产物能实际启动。数据库迁移与业务启动分开管理，测试使用隔离数据库。平台可独立使用，交付不依赖 GitHub/GitLab/Jenkins。

补充确认：产品由 Web 管理平台、Windows/macOS/Linux 桌面执行器和服务器执行器组成。D01 建立共享执行核心的进程入口；D03 验证本机浏览器控制；D09 完成节点绑定接入；D26 交付桌面安装包及安装升级流程。桌面壳技术在对应功能调研后确定，iPhone 首版执行节点仍需 Mac。

M0 验收覆盖登录、表单、查询、移动菜单，并加入目标站点实际需要的标签页、iframe、上传等样例。记录每端的首次成功、重试、定位失败及设备异常；原型重复执行用于发现问题，不作为性能或可靠性承诺。手机录制采集与 PC 录制分别验证，不把 codegen 当作已确认可直接嵌入的录制 SDK。

没有业务网站时可先使用 D02 的可控站点；真机、Mac、模型或相关授权缺失时，将对应验收明确标为阻塞，继续可独立执行的工作。模拟结果不能替代真机结果，缺少三端验证不能勾选 M0 整体完成。

V2 是后续交付范围，不阻塞 V1；同阶段任务按实际需求和资源安排。专用 GitHub/GitLab/Jenkins 对接不列为必做功能。依赖若需迁移已有版本或运行数据，应随对应功能给出升级验证。

## 8. 验证边界与开发记录

以下公共测试边界随本开发计划一并评审，在对应功能进入开发时落实；新增边界在其小功能计划中明确。

| 公共边界               | 验证重点                                                              |
| ---------------------- | --------------------------------------------------------------------- |
| Web 用户流程           | 登录、选择环境、录制/编辑/保存/试跑、报告、模型配置及人工接管         |
| HTTP API / WebSocket   | 身份、项目隔离、版本、任务状态与错误反馈，通过公开接口观察结果        |
| Runner / 驱动任务协议  | 正确及错误步骤结果、能力差异、租约、断线取消、事件与产物上传          |
| 模型与工具接口         | 生成步骤、能力不匹配、额度、调用失败、个人/团队凭据路径及环境动作规则 |
| 产物下载 / 分享 / 导出 | 可见范围、失效撤销、保留清理、离线包和基准引用                        |
| 启动 / 迁移 / 运维命令 | 真实 MySQL 迁移、服务启动、升级、备份恢复和配置错误提示               |

按 TDD 指南逐个行为建立红—绿验证，预期来自独立业务样例；只在外部模型、飞书、邮件、时间等系统边界使用替身。真实数据库用隔离实例验证，真实浏览器和设备结果单独记录。外部替身测试不能代替实际接入验收，也不测试私有方法或用数据库旁路代替 API 行为。

工程建立后执行适用 rules 中的格式、lint、typecheck，以及对应功能测试、构建与必要的三端验证。文档或低影响排版修改不增加镜像实现的测试。D01 的实际执行结果见 [功能交付说明](features/d01-engineering.md)。

开发时按 project-plan 流程：复核相关调研 → 用 to-tickets 拆当前大功能 → coding/TDD 实施 → 验证 → 更新功能说明及对应 skill → 交付该功能供 review。沿用已确认的范围和测试边界，实际缺口及范围变化明确记录。

通过 docs/progress.md 按本计划编号记录：未开始、进行中、阻塞、已完成待 review；当前功能列已做/剩余、阻塞原因及实际验证证据。plan.md 保留总体清单，仅在真正完成并验证后勾选，用户 review 状态单独记录；临时细分任务文档按相应 skill 生命周期管理。
