# D02 最小协议与可控测试站

日期：2026-10-29。范围为统一任务、步骤、能力、结果和事件协议，以及可供后续驱动反复验证的双环境演示站。验证记录见下文；完成后暂停供用户 review。

| -------------------- | ----------------------------------------------------------------------------------------- |
| `packages/contracts` | 版本化 TypeScript 类型、Zod 校验、环境和变量解析、能力预检、结果与事件一致性检查          |
| `apps/test-site`     | 两个独立 HTTP 实例；演示登录、表单、查询、重置、移动菜单、文件选择、同源 iframe、新标签页 |
| `examples/d02`       | 一份可运行验收的 JSON 任务、两套环境配置及样例能力声明                                    |

| 中文注释             | 按用户补充要求，已有项目源码、测试辅助和配置注释统一改为中文；第三方内容保持原样          |

正式录制、步骤编辑器、任务派发、录像和手机驱动仍由 D03 及后续功能交付。D02 的演示登录属于测试目标网站，与 D07 的平台账号无关。

## 方案复核

沿用 [原方案](../research/web-test-platform.md) 的 Playwright + Appium 双驱动和共享 JSON 用例，不重新引入另一套自动化引擎。

| 候选                           | 取舍                                                              | 本次决定                                 |
| ------------------------------ | ----------------------------------------------------------------- | ---------------------------------------- |
| 直接保存 Playwright 脚本       | PC 执行直接，但可视化修改与 Appium 转换需要解析代码               | 留作以后脚本扩展，不作为共享用例格式     |
| 保存原始 WebDriver/Appium 命令 | 接近协议底层，但环境、断言和编辑语义仍需自建，PC 也会绑定驱动细节 | 不作为产品用例格式                       |
| 版本化 JSON + TypeScript/Zod   | 统一人工录制、编辑和 AI 的输出，需要维护驱动适配及明确的语义      | 采用既有 Zod 4.6.7，不新增运行时技术选型 |

事实与依据（2026-10-29 复核）：[Zod 官方 strictObject / discriminatedUnion 实现](https://github.com/colinhacks/zod/blob/main/packages/zod/src/v4/classic/schemas.ts) 支持拒绝额外字段和按动作区分结构；实际行为以本仓库锁定版本和测试为准。[Node URL 文档](https://nodejs.org/api/url.html#the-whatwg-url-api) 定义基地址解析和 URLSearchParams，运行代码使用标准 URL API。驱动资料及许可沿用原调研的 Playwright/WebdriverIO/Appium 来源。

工程判断：跨环境复用通过逻辑站点、相对路径和显式变量实现，不做字符串替换。待验证：真实 PC/安卓/iOS 驱动的定位、等待和录像语义；样例能力声明不代表已有正式驱动或手机兼容性。

## 协议维护方式

统一从 `@riqvo/contracts` 导入，不引用包内部路径。构建产物为 CommonJS 和 `.d.ts`；协议代码不依赖 Node 进程、文件系统或浏览器控制器。

| 公共入口                          | 用途                                                                       |
| --------------------------------- | -------------------------------------------------------------------------- |
| `parseTask(input)`                | 校验任务结构、唯一步骤 ID 和协议版本，返回独立快照                         |
| `parseCapabilities(input)`        | 校验驱动当前会话的显式能力声明                                             |
| `prepareTask(task, capabilities)` | 解析地址和变量，返回 `ready` 步骤，或不含可执行步骤的 `unsupported` 及原因 |
| `parseRunResult(task, result)`    | 检查报告与任务、尝试编号、步骤顺序、时间和最终状态一致                     |
| `parseRunEvent(task, event)`      | 校验单条事件归属；最终事件复用报告一致性检查                               |

当前 `protocolVersion` 为 1。未知版本、动作和额外字段会被拒绝；不默默删除未知内容。后续协议变化须记录版本兼容方案并更新样例及契约测试。`ContractError.code` 是稳定错误标识，错误文字不回显用户输入。

### 任务、地址与变量

任务固定 `id`、`attempt`、用例 `case.id/version/steps`、环境 `environment.id/revision/name/sites`、目标 `target`、变量和产物种类。环境 ID 和名称可自定义，不限于测试或正式环境；示例使用测试和预发布。

导航保存 `site: "portal", path: "records"`，不保存完整业务地址。站点 `https://example.test/app` 视为目录基地址，解析结果为 `https://example.test/app/records`。查询参数通过单独的 `query` 对象编码，禁止在 `path` 中混入查询、片段、绝对地址、上级目录、反斜线和编码后的路径分隔符。基地址不接受用户信息、查询或片段。

输入值采用 `{ "source": "literal", "value": "文本" }` 或 `{ "source": "variable", "name": "keyword" }`。缺少站点或变量时失败，变量内容不会作为代码或模板再次执行。`prepareTask` 不改写原始用例和环境快照。

这只是声明式 URL 解析，不构成网络授权或 SSRF 防护。页面自身跳转、SSO、环境动作权限、敏感账号引用与会话注入在后续功能处理。当前变量仅用于普通测试数据；示例密码为公开演示值，不能用本示例存放真实凭据或模型 Key。

### 步骤和能力

| 动作            | 语义                             |
| --------------- | -------------------------------- |
| `navigate`      | 打开解析后的站点相对路由         |
| `fill`          | 用字符串替换输入框内容           |
| `select`        | 按 value 选择单个选项            |
| `check`         | 将复选框设置为指定布尔值         |
| `click`         | 点击唯一匹配元素                 |
| `waitFor`       | 等待元素可见或隐藏；不算业务断言 |
| `assertText`    | 文本完全相等或包含期望字符串     |
| `assertVisible` | 断言可见或不可见                 |
| `assertUrl`     | 断言地址等于环境解析后的完整地址 |
| `screenshot`    | 申请截图产物；不算业务断言       |

默认步骤超时 30 秒，可配置 1～300000 毫秒；当前单任务最多 1000 个步骤。定位支持 testId、role + name、label、CSS；语义定位默认精确匹配。执行器必须拒绝多元素歧义，不能默认取第一个。D02 只定义主页面的最小动作；iframe、文件、标签页和复杂交互已提供目标站样例，对应驱动及协议扩展在后续功能验证。

能力声明分别列出平台、浏览器、运行模式、动作、定位方式和产物类型。任何所需能力缺失都返回 `unsupported`，不静默降级或跳过。`background` 表示执行方式选项，不表示手机具备无屏浏览器能力。

### 结果、事件与产物

- 最终状态为 `passed`、`failed`、`cancelled`、`unsupported`、`unverified`。所有步骤完成且通过、至少包含一个业务断言，才允许标记 `passed`。无断言或有跳过时使用 `unverified`。
- 结果步骤对应任务中的有序前缀，不能重复或指向其他步骤；失败、取消或不支持后只能继续标记跳过。成功结果必须包含完整步骤。时间使用 UTC ISO 字符串，结束不得早于开始，也不能超出任务时间。
- 每个重试尝试单独使用 `attempt`（当前协议 1～100），与首次尝试的结果区分。此处不执行自动重试；策略在 D17 实现。
- 错误用固定代码表示，可附诊断 ID；不接受原始输入、绝对文件路径或任意错误文本。
- 截图、视频和 Trace 使用不透明引用 ID，状态为 `available`、`missing`、`expired`。录像失败可单独报告为产物缺失，不混同业务断言失败；本阶段不校验实际媒体文件或提供上传下载。
- 事件为 `run.started`、`step.started`、`step.finished`、`artifact.recorded`、`run.finished`；绑定任务、尝试编号、递增序号和时间。D02 校验单条事件，跨消息排序、去重、持久化和状态机在 D09/D16 实现。

## 可控站点的运行与限制

在 Node 22 下执行 `pnpm fixture:start`，命令构建后启动端口 4174（test）和 4175（preprod）的两套演示实例；Ctrl+C 停止两者。使用自定义端口可执行：

```bash
pnpm --filter @riqvo/test-site build
node apps/test-site/dist/main.js --port=4176 --environment=staging
```

站点仅监听本机回环地址，独立于平台的 `pnpm dev`，不访问平台 MySQL/Redis。会话 Cookie 按环境与端口隔离，记录保存在当前实例内存中。每次重新登录建立空会话；每个会话最多 100 条记录，最多 200 个有效会话，1 小时失效；重启清空。页面提供“重置我的数据”，不会操作其他会话。

测试目标使用原生 HTML 表单和 TypeScript，以覆盖浏览器标准控件和稳定语义定位；它不是平台管理台的组件示例。平台管理台继续采用 Vue + Naive UI。文件选择仅展示本地名称及大小，iframe 仅处理页面备注，新标签页展示说明；不存在生产上传或消息发送。

当前只验证 Linux x64 上的 Chromium，以及 390px 的布局；不能据此声称手机真机、Safari、Chrome/Edge 产品驱动或跨域 iframe 已验证。手机访问测试站的受控网络链路在 D04/D05 接入时处理。
